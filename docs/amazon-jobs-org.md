`amazon-jobs-org-open.json` opens the human assignment before any work.
`amazon-jobs-org-audit.json` records the host command's source, baseline,
offline test, independent verdict and live source-only queries. These are
**workflow definitions**, not executed receipts. The independent admission stage calls the actual ai-ci verifier against
`contracts/amazon-jobs-cli-v0.contract.tsv`, whose five semantic-boundary
assertions each have a deliberately broken fixture. The verifier revision
is recorded. This is **structural acceptance only**: compiler execution,
real-provided fixture behavior and complete feed integrity remain separate
admission obligations before Blackball accepts a current map.

The separate Software Development stage requires `--all`, stable `hits`
and distinct numeric requisition IDs. Failed transport, endpoint changes or
pagination inconsistency produce nonzero exit status. An unrelated web
answer, fixture or Python replacement is prohibited for new Amazon jobs
observations in this audit.

The dated historical baseline (September 16, 2026) must not be rewritten.
A current observation is a separate time-indexed stock. Compare counts,
record IDs, source metadata, narrower work descriptions, evidence levels
and worker-access gates. The live endpoint cannot demonstrate firing
causality, actual hires, payroll headcount or formal reporting relationships.

Do not add a scheduler that bypasses this job envelope. The runner's
command-stage output captures stdout/stderr/exit code and source hashes.
A new Blackball claim is admitted only after the exact receipt and
independent AICI verification are attached. Hosted execution and live
Amazon.jobs access remain NOT_VERIFIED until performed.
