# CF-A2-S6 integration candidate

Status: **BLOCKED**, partial implementation. The maintained result still requires
Cat Food S2's approved immutable application plan, AICI S4's independently
qualified shared producer decision, Kitchen S5's exact maintained procedure,
and Cat Food S3's independent acceptance consumer. The preserved predecessors
do not supply these new contracts. Local uncommitted successor work is not an
immutable dependency pin. No replacement runner or Cat Food plan schema is
created here.

The isolated integration continues retained FP3 source and incorporates the
FP2 evidence/qualification updates and active paired conversation producer.
Current main's handoff, attachment and other pipeline code is retained. The
legacy controller is explicitly `run-pipeline-legacy.py`; its green regression
does not grant Android producer authority.

The existing registered Android controller now records request, deployment,
plan, profile, capture configuration, launcher, DEX, complete tracked leaf
source, relevant implementation/runtime bytes and predecessor revisions.
Each stage binds run, attempt, plan and material digest. It rechecks inputs
before and after children, records raw child exit separately from stage result,
requires fresh stage output and independently bound decision output, and keeps
partial attempts. Repeated/concurrent host diagnostic attempts use different
private directories. Earlier receipts are not an authorization input. FP2
cached attempts additionally reject changed qualification/contract/materials.

The current diagnostic predecessor still supports only the historical A1
candidate. This is not the S2 resolver or paired procedure family. Hosted
diagnostic fixtures carry bounded-observation scope, no accepted package and
independent A1/C67 physical fields `NOT_RUN`. The observation profile can contain
declared instance identity; it cannot establish physical handset acceptance.
Production Android paths reject with `S6_PREDECESSORS_UNQUALIFIED` before task
execution. Explicit caller-owned deployments admit qualification scope only.

`android-conversation-paired-build` reserves a data-only request containing
`pipeline`, `request_id`, and `application_plan_sha256`. This is an FP intake
reservation, not a Cat Food plan format. Its exact production request interface
must be reconciled against published S2 before admission. Both workflow dispatch
and immutable request-branch intake reach the same existing controller and
return `MISSING_PREDECESSOR` before Android execution. Direct historical
`build.pi` rejects with `UNAUTHORIZED_DIRECT_PRODUCER`. The original source,
toolchain gaps, stripped-artifact identities and independent physical jobs are
preserved as historical cross-build evidence.

## Examples and expected boundary

On an installation containing the independently delivered registered client,
the terminal form is `/opt/flexible-pipes/current/scripts/run-pipeline
android-conversation-paired-build --request /absolute/data-request.json
--runs-root /var/lib/flexible-pipes/android-runs`. This is an invocation shape,
not a claim that the installation exists. Missing runtime/controller fails with
`MISSING_RUNTIME`; the retained paired candidate then fails with
`MISSING_PREDECESSOR`. Do not install or activate services to make this example
pass within S6.

The candidate data request is:

```json
{"pipeline":"android-conversation-paired-build","request_id":"paired-example","application_plan_sha256":"<actual Cat Food approved plan SHA-256>"}
```

An actual digest must replace the placeholder; inventing one cannot admit a
plan. For dispatch, supply these exact JSON bytes as the `request` input of the
canonical-main workflow. For branch intake, the sole changed regular blob must
be `requests/paired-example.json`, compared as immutable Git objects against
the admitted canonical base. Branch code is not executed. Both routes remain
inactive without signed admission and independent installed promotion.
