failed to load; it was not evidence against the Venn mathematics.

## Repairs and observations

The consumer checker selects the exact bootstrap prefix, rejects error
diagnostics as well as failing statuses, requires a fresh executable,
invalidates old success, and keeps log names distinct on case-insensitive
artifact storage. Fixture constants are qualified and implicit rebinding is
disabled with `%unbound_implicits off`. The semantic model was not replaced or
weakened. Runtime component hashes supplement the insufficient launcher hash.

A complete local FP run passed on Ubuntu 24.04 x86-64: nine intended type
rejections, 768 independent oracle queries, 392 movie queries, five rejected
output corruptions, and 196 rendered/decoded frames at 1600×900 and 24 fps.
The local movie SHA-256 was
`d164e155992d6ad42dec6db0c35c9edd7fc751ff45f32f9e9a0e9e1808fed708`.
First and last images were inspected. This run used a working-tree repair:
the recorded Git HEAD alone does not identify all changed bytes. Hosted
acceptance must bind the subsequently committed revision.

The checked-Ithon regression in `examples/autogenerated/venn-compiler-diagnostics`
accepts a clean twin, rejects four diagnostic/status failures, and checks stale
success invalidation. It tests the adapter, not Idriç proofs. Its frontend pin
is the existing qualified interface `d6e83969f82512e920fb17b44326cb54f31d015c`.
