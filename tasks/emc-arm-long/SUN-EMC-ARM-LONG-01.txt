## Non-negotiable naming and type policy

1. Every physical ARM general register `r0` through `r15` is an atomic singleton type. Preserve exact aliases (`sp`, `lr`, `pc`, `ip`, etc.) as references to the **same** physical register, not new ones. Give VFP/NEON registers and special machine state their own explicit typed families. An unknown name or illegal role must fail, not degrade to arbitrary `Text`.
2. Every architecturally distinct instruction/encoding form is an independently identifiable atomic instruction **type**, with checked operands, machine/profile eligibility and an exact mapping to its encoding. Do not simulate distinctness by putting all mnemonics into one undifferentiated `Text` or `Number` enum. Dependent/indexed instruction types are appropriate where they strengthen operand guarantees.
3. **No assembler shorthand internally.** `LSL`, `STRD`, `BL`, `LDR`, `MOV`, `BIC`, etc. may occur only in input lexer tables, external assembler/disassembler output, pinned ISA references, original source fixtures and explicit origin/encoding metadata. Use full semantic English for constructors, functions, IR tags, rendered names, documentation of the language and generated operation descriptions. Example forms (refine against actual encoding): `shift_thirty_two_bit_register_contents_left_and_fill_low_bits_with_zeroes_without_changing_condition_flags`; `store_two_adjacent_thirty_two_bit_register_values_at_computed_memory_addresses_without_base_writeback`; `branch_to_target_and_save_return_address_in_link_register`. Separate names when flags, addressing, writeback, exception, ISA state or semantics differ. Machine `A1`/`T1`/`T2` identifiers remain **encoding metadata**, not substitutes for English.
4. **Repair PR #18 now**: migrate `opcode_push_a1`, `move_register`, `load_word`, `clear_bits_asr`, `describe_instruction` outputs, etc. to full-English semantic names wherever they are internal. Retain assembly mnemonics and hexadecimal words as provenance. Run searches/tests so no shortened instruction names leak across the typed IR, JSON schema, generated prose, or user-facing semantic representation. Register spelling such as `r12` is an approved physical-register identity, not an opcode abbreviation.
5. A long name **does not replace** a verified state-transformer definition. Keep exact side effects separately checkable: explicit and implicit register reads/writes; flag update versus preserve versus architecturally undefined; memory widths, endianness, access permissions, alignment, address calculation and writeback; conditional execution; PC-operand read versus the separately defined **execution index**; exceptions, ordering, privilege, ISA state and ABI.
