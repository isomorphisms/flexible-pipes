2. Verify the current API

Official documentation:

- https://jobicy.com/jobs-rss-feed
- https://jobicy.com/api/openapi.json

The documented public endpoint is:

"GET https://jobicy.com/api/v2/remote-jobs"

Implement its supported parameters:

- "count": 1–200 jobs per page.
- "geo": geographic eligibility.
- "industry": job category.
- "tag": keyword.
- "cursor": opaque pagination token.

The current API also documents:

- "nextCursor" and "hasMore".
- "?get=locations" and "?get=industries".
- "/api/v2/remote-jobs/status?ids=..." for batch status checks.

Refresh the older notes against the actual OpenAPI specification. Record the specification version and digest.

The public API requires no credentials. Do not activate paid commercial API features or consume paid application-link credits.

3. Implement the program

Required executable: "jobicy".

Required command surface:

jobicy help
jobicy version
jobicy doctor

jobicy locations
jobicy industries

jobicy url --count 20 --geo usa --tag mathematics
jobicy search --count 20 --geo usa --tag mathematics
jobicy search --geo usa --industry engineering

jobicy search --geo usa --all
jobicy status 123456 123457

jobicy fixture FILE

"--all" must traverse sequential cursor pages with a documented safety bound. It must not run an unbounded request loop.

Provide TSV and JSONL output. Both must be suitable for downstream programs.

Each job record must preserve:

- Exact Jobicy job ID.
- Employer and title.
- Geographic eligibility and employment type.
- Seniority and industry.
- Publication timestamp.
- Salary bounds, currency, and period when supplied.
- Canonical Jobicy source URL.
- Original job description, without silently discarding substantive text.
- Source and observation provenance.

Do not invent missing salary information or treat remote work as permission to work from any country.

Keep full descriptions available for later mathematical-proof employment research.

4. Correct pagination and status

Implement actual cursor traversal.

- Preserve filters across pages.
- Treat cursors as opaque.
- Deduplicate by exact job ID.
- Detect repeated cursors and inconsistent pagination.
- Distinguish an empty successful response from an API failure.
- Do not interpret a partial traversal as the complete feed.

Jobicy's public feed covers a limited recent publication window. It is not a nationwide employment census.

Implement status checks using the documented batch endpoint.

Preserve the distinctions:

"active ≠ closed ≠ unknown"

Disappearance from the recent feed does not prove that a posting closed.

Respect provider limits, caching guidance, and throttling responses. Automated synchronization must not start more frequently than permitted by the provider.

5. Compile and install

Idriç owns command parsing, request meaning, JSON decoding, validation, and output.

ICU/Idric-Net owns networking. ICK owns the maintained applicable native build stage.

Do not add a Python, JavaScript, curl, or C++ substitute implementation.

Provide reproducible build commands and an actual install target, such as:

make jobicy
make install-jobicy
make jobicy-test

Use Kitchen to preflight the real host and dependencies.

Test the installed command from outside the repository, not just a source-tree invocation.

Prioritize MIRO A1 ARM32/Termux qualification where accessible. Record C67 ARM64 separately. Do not claim physical-device acceptance from Linux-only results.
