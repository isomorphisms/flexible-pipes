Source review dated 2026-10-14 UTC / 2026-10-13 America/Detroit

DECISION

The concrete 32D defect is confirmed. The source interface does not establish a vector/covector pair in a 32-dimensional space. It computes a sum of eight four-component products and puts the result in three colour channels. Repair the checked mathematical interface and retain packing only below that boundary.

This is not only a naming problem. The rotation example has a mathematical counterexample in its small-input path. Precision labels and verification labels also require narrower contracts.

Reuse the existing Idriç semantic work. Do not build another unrelated geometry hierarchy in the shader backend. Do not make aliases of rejected names part of the permanent interface.

INVENTORY: CONFIRMED PROBLEMS AND PRECISE REPAIRS

N01 — DotVector32Covector32 / dot_vector32_covector32.
Actual: sixteen SVec 4 inputs; eight dot calls summed; output vec4(result,result,result,1). No 32D type, named space, basis, scalar-field declaration, or dual-role distinction in the signature.
Evidence:
https://github.com/fuego-ironworks/idris-shader-backend/blob/4a29362e580df393e4d64a9929e4c1e592ac4c53/src/Example/DotVector32Covector32.idr
Repair: one checked vector operand and one checked covector operand of the same 32D space; canonical pairing returns a scalar. A separate rendering wrapper maps a numerical result to RGBA. Preserve the 8×4 packing as a derived target interface.
If retained solely as a low-level primitive, use a name such as sum_32_paired_products_packed_8x4_to_rgba. Such an accurately named primitive does not itself implement the missing mathematical abstraction.

N02 — DotVector4Covector4, u_vector/u_covector, vector32/covector32.
Actual: the 4D example also takes two SVec 4 values. Native GLfloat arrays carry no dual-role contract. Variable names in the runner do not establish the relationship.
Evidence: src/Example/DotVector4Covector4.idr; tools/powervr_primitives.c, especially uniform uploads and readback labels.
Repair: migrate both examples, native bindings, benchmark labels, generated filenames and checks. A numerical packet can have accurate fields such as vector_coordinates or covector_coordinates only when it is produced/validated through the corresponding semantic interface; otherwise use left_components/right_components.

N03 — SVec, TVec, SomeVector, vectorDot, RDot.
Actual: opaque source shader values with component counts, lowered to GLSL vec2/3/4. The API offers component arithmetic, but neither field/space identity nor dual/metric roles. The same carrier also holds complex numbers, colours, phase/log-modulus pairs and diagnostic records. Signature parsing restricts component count to 2–4.
Evidence:
https://github.com/fuego-ironworks/idris-shader-backend/blob/4a29362e580df393e4d64a9929e4c1e592ac4c53/src/Shader/Source.idr
https://github.com/fuego-ironworks/idris-shader-backend/blob/4a29362e580df393e4d64a9929e4c1e592ac4c53/src/Backend/GLSLES/IR.idr
Repair: expose ShaderFloatTuple(component_count) or another explicitly numerical carrier at this layer. Mathematical Vector and Covector live above it. Rename low-level RDot to a component-product reduction unless it carries the necessary semantic distinction. Keep GLSL's required vecN token unchanged. Do not replace “vector” with “register” here: GLSL values do not establish physical register allocation.

N04 — RotateDifference8ToE1.
Actual: subtracts two packed 8-component operands, constructs a Householder-style expression using a clamped divisor, conditionally flips coordinate two, and returns an axis ratio and residual encoded as RGBA. It does not return a rotation object or the complete transformed vector.
Evidence:
https://github.com/fuego-ironworks/idris-shader-backend/blob/4a29362e580df393e4d64a9929e4c1e592ac4c53/src/Example/RotateDifference8ToE1.idr
Confirmed functional defect: below the cutoff the normal is not unit length, so I−2uuᵀ is not generally a reflection. See the exact counterexample below.
Repair: construct and apply an actual orientation-preserving orthogonal map under a stated numerical contract. Separate input-dependent alignment selection from application of the resulting fixed linear map. A remaining diagnostic wrapper must say it returns alignment diagnostics.

These are vocabulary proposals, not claims of compiled new identifiers. Choose actual Idriç spelling from current language conventions. Do not encode every mathematical abstraction into the language core: use the existing mathematical library and narrow typed compiler interfaces.

A finite-precision encoding is not a field. Mathematical laws belong to the semantic object; numerical operations approximate them under a stated contract. Tests must not falsely demand exact associativity of ordinary floating addition.

A low-level GLSL dot can implement either a coordinate contraction or an inner product after the semantic decision is settled. Its identical emitted formula does not erase the distinction in the source contract.

For complex scalars, explicitly distinguish the linear dual from a Hermitian inner product, including which argument is conjugate-linear. Do not assume that a real-coordinate dot on two component tuples is complex dual pairing.

EXACT COUNTEREXAMPLE TO THE CURRENT ROTATION CLAIM

Let ε be the literal clamp threshold, and choose difference d=(0,ε/4,0,…,0). Write r=ε/4.

The target is (r,0,…), so the raw Householder normal is (−r,r,0,…). Its norm is √2 r, below ε. The implementation therefore uses u=(−1/4,1/4,0,…) instead of a unit normal.

The computed reflected vector is:
d − 2u(u·d) = (r/8,7r/8,0,…) = (ε/32,7ε/32,0,…).

The branch condition is false, so no coordinate-two reflection follows. The squared output norm is (25/32)r², not r². The norm ratio is √(25/32), approximately 0.884.

This is an exact algebraic failure in the algorithm, independent of floating rounding. It neither aligns the chosen input with the first axis nor preserves its norm. A rename alone cannot repair a rotation API.

The source also exposes a more general distinction: d ↦ R(d)d chooses a different R from each d. That overall alignment operation is not one fixed linear transformation. Construct R from a reference input, then test application of that same R to other vectors.

INDEPENDENT ACCEPTANCE CORPUS — SPECIFIED, NOT EXECUTED

T01: 32D basis pairing.
For every i,j from 1 to 32, evaluate the i-th dual basis covector on the j-th basis vector. Expect 1 when i=j and 0 otherwise. Include off-diagonal cases across each 4-component packing boundary. A dropped chunk, duplicate chunk or independent permutation of only one operand must fail. Pairing the final coordinate is mandatory.

T02: Nonorthogonal basis change.
In old coordinates take vector (2,3), covector row (5,7), and new basis columns B=[[1,1],[0,1]].
Old pairing = 31.
New vector coordinates B⁻¹v = (−1,3).
New covector coordinates αB = (5,12).
New pairing remains 31.
Treating the covector as another vector gives (−2,7), producing 23 instead: reject.
Embed this block in 32 dimensions. Do not use only orthogonal basis changes, which can conceal the dual-role error.

T03: Metric is separate from pairing.
For the same basis change, old Euclidean squared norm is 13.
New Gram matrix BᵀB=[[1,1],[1,2]] gives 13.
An ordinary component-square sum in the new coordinates gives 10: reject that as the same metric.
Wrong basis/space/metric combinations must require an explicit transformation rather than implicit reinterpretation.

T04: Complex distinction, when complex scalar support is enabled.
A complex linear functional with coefficient 1+i evaluated at 1+i gives 2i. A Hermitian squared norm gives 2. Require the declared operation and conjugation convention; a shared two-real tuple must not make these interchangeable.
Until enabled, unsupported complex contracts must be explicitly rejected rather than treated as accepted real tuples.

T05: Negative checked interfaces.
Wrong dimension, different named spaces with equal dimension, covector passed as vector, vector passed as covector, absent metric, wrong coordinate frame, and unrelated declarations named SVec/SArray/dot/normalize. Each needs a passing neighbour and the intended diagnostic.
Explicit unsafe extraction/reconstruction remains an explicitly unsafe operation, not evidence that the checked interface failed.

T06: Rotation operator.
Positive 2D block R=[[3/5,4/5],[-4/5,3/5]], identity on other coordinates: R(3,4)=(5,0), determinant +1 and exact Gram identity.
Negative H=[[3/5,4/5],[4/5,−3/5]] also aligns (3,4), but has determinant −1. Reject H as a rotation.
Test basis images and arbitrary additional vectors with a single previously constructed map. Check inverse/composition, inner products and last coordinates. An alignment-result-only test cannot distinguish the two maps.

T07: Small-input rotation.
Preserve the ε/4 counterexample above, plus zero, positive/negative first axis, near-axis cancellation, scale changes and nonfinite inputs. Exact fixtures establish mathematics; floating runs use justified absolute/relative/ULP bounds. Do not derive tolerances merely by observing a passing implementation.
If a tiny-input identity policy is chosen, test its explicitly limited alignment promise separately.

T08: Packing and storage.
Compare unpack(pack(coordinates)) against independent coordinates, and pairing results across 4-wide chunks and another supported packing.
Use a dimension requiring padding, such as five components in two 4-wide tuples. Poison padding and prove it cannot enter the mathematical result.
Reject wrong order, stride, byte length, scalar encoding, schema version and mismatched operand roles. Distinguish fixed arrays from linked containers.

T09: Indexing.
Test 0 and length−1 as valid. Reject or explicitly diagnose −1, length, fractional values, NaN and infinity at the declared indexing/conversion boundary. Exercise conditional/loop access without evaluating rejected out-of-range paths.

T10: Effective precision.
Test numeric behavior at representable boundaries rather than IR label spelling. For example, under an explicitly declared binary16 round-to-nearest-even addition, 1+2⁻¹¹ rounds to 1; binary32 can represent that exact sum.
State rounding, subnormal, overflow and contraction policies, and use enough independently selected cases to distinguish them. One sample does not prove full format conformance.
An incompatible precision override must fail or produce a honestly different relaxed contract.

T11: Verification labels and implementation provenance.
Feed real generated artifacts and targeted constant-colour, handwritten-fallback, wrong-source-hash, stale-device, wrong-renderer, mislabeled mock and assembly-only receipts.
A receipt claiming physical execution must fail when only assembly is present. A numerical comparison must name cases and tolerance. A proof must name its proposition and exact proof checker/revision.
A source-level proof does not automatically survive an unverified compiler transformation.

T12: Full numerical observation.
Read the actual scalar or all transformed coordinates before colour quantization. Use a qualified floating readback path or an independently specified encoding whose range/error is sufficient. Existing RGBA8 clamps/quantizes values and cannot establish exact arithmetic, all-coordinate behavior or orientation.
Keep ordinary colour-readback checks as colour-readback checks.

These checks belong in the reusable ai-ci acceptance boundary, with consumer fixtures. Every required assertion needs a good case and a targeted bad implementation that fails for the intended reason. Job 04 must implement and execute this corpus before it can be called an independent test suite.
