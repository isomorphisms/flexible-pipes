# A1 and C67 native producer

Inputs: one native source identity, Cat Food's ordered device/ABI/API matrix,
qualified ICK identity and the Android NDK. Output: two stripped ELF artifacts,
their digests/sizes, stage commands, failed ICK attempts and build receipts.
Processes, files, hashing and subprocess completion are control-plane actions.
The shared AICI consumer contract selects checked Ithon for this control code.
The model's Idriç Float32 failure remains in takeout-svm; this program makes no
Idriç execution claim.

The A1 is primary and uses ARMv7/armeabi-v7a; the paired C67 uses arm64-v8a.
Neither device is a compilation host. The producer attempts the existing
AArch64 ICK C object stage for the C67, preserving an unsuccessful command and
diagnostic. Its concrete NDK r29 Bionic nullability/availability-header failure
justifies the NDK object fallback on this stage. The available ICK executable's
`aarch64-linux-gnu` target does not cover the A1's ARMv7 ABI. NDK linking is
recorded separately. These are exact available-artifact gaps, not a claim that
all ICK configurations lack Android support.

ELF inspection follows stripping. Successful producer completion is
`CROSS_BUILD_ONLY`; physical runtime fields remain `NOT_RUN`. The first language
work for the model is preserving its Float32 vector boundary; the first
producer acceptance after build is raw-text execution on the exact A1 artifact,
with matching source/model digests and cold/warm timing and memory receipts.
